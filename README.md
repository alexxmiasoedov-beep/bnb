# fmcopy — отбор кошельков Four.meme для копи-трейдинга

Собирает из блокчейна BNB Chain все сделки лаунчпада Four.meme, для каждого
активного кошелька **симулирует копирование по нашим правилам** и отбирает
кошельки, которые приносят прибыль именно копировщику, а не только себе.

Только Python 3.10+ из коробки, внешних зависимостей нет.

## Правила копирования (заложены в симуляцию)

- Вход — фиксированно **0,1 BNB** (`FM_ENTRY_BNB`), только на **первую** покупку
  кошелька в токене. Если кошелёк уже покупал этот токен — не копируем;
  его докупки игнорируем.
- Выход — пропорционально: кошелёк продал X% своего остатка → продаём X% своего.
  Перевод токенов на другой адрес считается продажей. После выхода токена на
  PancakeSwap следим за переводами кошелька там же.
- Исполнение с задержкой k блоков (~0,45 с на блок) по точной формуле кривой
  Four.meme (constant product, виртуальный резерв ≈6,16 BNB, комиссия 1%),
  плюс газ. Считаем при k = 1, 2, 3; ранжируем по k = 2.
- Страховка: стоп-лосс −70%, выход при простое токена 24 ч, принудительное
  закрытие через 72 ч после выхода на PancakeSwap.
- Берутся только токены, которые торгуются за BNB (≈25–40% запусков,
  остальные — за USDT, USD1 и токенизированные акции) и созданы внутри окна,
  чтобы вся история кошелька в токене была видна.

## Отбор

Окно делится на обучение (первые 75%) и проверку (последние 25%).
Кошелёк отсеивается, если на обучении:

| Фильтр | Порог |
|---|---|
| первых покупок | < 30 |
| создатель токенов | > 30% входов |
| снайпер (≤3 блоков от создания) | > 50% входов |
| сделок в день | > 100 (бот) |
| медианное удержание | < 45 с (не успеем выйти) |
| его покупка двигает цену > 15% | > 30% входов |
| «приманка»: продаёт ≥50% за ≤10 блоков | > 30% входов |
| ожидание копии на сделку | ≤ 0 |
| профит-фактор | < 1,5 |
| PnL без двух лучших сделок | ≤ 0 |
| доля прибыльных недель | < 75% |
| PnL при задержке 3 блока | ≤ 0 |

Прошедшие ранжируются по t-статистике доходности сделок (среднее / разброс ×
√n). Из кошельков, которые часто входят в один токен в одном блоке (один
игрок), остаётся лучший. Статус «ОТОБРАН» получают те, у кого ожидание на
проверочном периоде тоже положительное. На проверке считается портфель из
топ-15: один токен — одна позиция, за первым вошедшим кошельком.

Все пороги — в `fmcopy/config.py`, многие переопределяются переменными
`FM_<ИМЯ>` (например `FM_MIN_SIGNALS=20`).

## Запуск

```bash
python -m fmcopy collect --days 14   # события Four.meme за 14 дней → data/fourmeme.sqlite
python -m fmcopy postmig             # пары PancakeSwap для вышедших токенов
python -m fmcopy select              # симуляция и отбор → reports/
python -m fmcopy wallet 0xADDR       # разбор одного кошелька: капа входа, его PnL и PnL копии
```

`collect` можно прерывать и перезапускать — продолжит с последнего блока;
повторный запуск позже докачает новые блоки.

По умолчанию используется публичный узел NodeReal с полной историей: он
ограничивает частоту, поэтому 14 дней качаются порядка часа. Свой ключ
(NodeReal, Ankr, QuickNode — бесплатного тарифа хватит) ускорит:
`export FM_RPC_URL=https://...`. Бесплатный ключ Etherscan BNB Chain не
покрывает.

## Результат

- `reports/report.md` — сводка: отобранные кошельки, портфель на проверке,
  почему отсеяны остальные.
- `reports/wallets.csv` — все кандидаты со всеми метриками.
- `reports/portfolio_trades.csv` — сделки портфеля на проверочном периоде.

## Ограничения

- Задержка копии в жизни должна быть не хуже заложенной (2 блока ≈ 1 с).
- Кластеры ищутся только по совместным входам в одном блоке; связь кошельков
  через пополнения BNB не отслеживается.
- Если кошелёк покупает через контракт-посредник, в событии может стоять адрес
  посредника — такие «кошельки» отсеются фильтром по числу сделок.
- Это инструмент анализа, а не торговый бот: исполнения сделок здесь нет.
